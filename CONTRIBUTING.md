# Contributing to Craftsman

Thank you for your interest in contributing to Craftsman!

Craftsman is an evidence-based quality gate that makes AI coding agents prove they reviewed and tested their changes before declaring "done".

---

## Guiding Principles

1. **Zero Runtime Dependencies**: The runtime code in `craftsman/` relies strictly on the Python Standard Library (`dependencies = []` in `pyproject.toml`). No external runtime dependencies are permitted.
2. **Strict Type Safety**: All source code (`craftsman/`, `scripts/`, `tests/`) must pass `mypy --strict` without errors or `# type: ignore` suppressions.
3. **Evidence-Based Quality**: Every change must be verified by automated tests and maintain clean working tree hygiene.

---

## Development Setup

### Prerequisites
- Python 3.10, 3.11, 3.12, or 3.13
- Git

### Initializing Environment
```bash
git clone https://github.com/BuczynskiRafal/craftsman.git
cd craftsman

# Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate  # On Windows: .venv\Scripts\activate

# Install development dependencies and editable package
pip install --upgrade pip
pip install -e ".[dev]"
```

## Local Verification Gate

Before submitting a pull request, ensure all checks pass cleanly:

```bash
# 1. Lint with Ruff
python3 -m ruff check craftsman scripts tests

# 2. Type check with Mypy (strict mode across all files)
uvx mypy --strict craftsman scripts tests
# or: mypy --strict craftsman scripts tests

# 3. Run the full unit and integration test suite
python3 -m unittest discover -s tests -v

# 4. Verify system diagnostics in an isolated environment
HOME=$(mktemp -d) python3 -m craftsman.cli doctor
```

## Git Workflow & Commit Guidelines

### Branching Model
- Work strictly on feature branches branched off `devel`:
  ```bash
  git checkout devel
  git pull origin devel
  git checkout -b feat/my-new-feature
  ```
- Submit pull requests targeting the `devel` branch.
- The `main` branch is reserved for tagged production releases. Direct pushes to `main` are strictly forbidden.

### Commit Messages
- Use atomic **Conventional Commits** in American English:
  - `feat: ...` for new features or enhancements
  - `fix: ...` for bug fixes
  - `docs: ...` for documentation changes
  - `test: ...` for test suites or verification fixtures
  - `refactor: ...` for behavior-preserving code restructuring
  - `chore: ...` for build, metadata, or maintenance tasks
- Author commits using your real identity (`git config user.name` and `git config user.email`).
- Do **not** include AI attribution trailers (`Co-authored-by:`, `Generated by`).

## Extending Craftsman

### Adding a Review Lens
1. Define the lens identifier, title, focus, and the risk signals that suggest it (`triggers`) in `craftsman/lenses.py`.
2. Write its goal and probes in `skills/craft-review/lenses.md` under a `` ## `<id>` — <title> `` heading (`craftsman/playbooks.py` slices the file on these headings).
3. Add unit test coverage in `tests/test_lenses.py` and `tests/test_playbooks.py`.

### Adding a Risk Signal
1. Add the signal name to `SIGNALS` in `craftsman/diffscan.py` and its content patterns to `craftsman/diffscan_signals.py`.
2. Map the signal to the lenses it suggests through their `triggers` in `craftsman/lenses.py`.
3. Add unit tests in `tests/test_diffscan_signals.py` (patterns) and `tests/test_lenses.py` (lens suggestion).

### Supporting an Agent Platform
1. Implement platform hook adapters in `craftsman/hooks.py` and `craftsman/install.py`.
2. Define hook lifecycle manifests in `hooks.json` or platform-specific settings exporters.
3. Test platform payload round-tripping and error visibility in `tests/test_hooks.py`.

### Claude Code Plugin Files
The repository root is the Claude Code plugin. `.claude-plugin/` holds its generated files: the
manifest (with the hooks), the marketplace catalog, and the agents rendered from `templates/agents/*.md`.
After changing an agent template, a hook event or the version, run `craftsman export --claude-plugin`;
`tests/test_platform_claude.py` fails while they are out of date.

### Altering Review Protocol
The protocol lives in prompts (`skills/`, `templates/agents/`, `rules/`) and in the gate (`craftsman/gatecheck.py`); keep each prompt line earning its tokens. Before proposing changes to review lenses, the hunt protocol, or gate invariants, replicate the benchmark suite (`bench/run.py` against `bench/cases/`, the maintainer's private harness) and run the public seeded-defect suite (`python3 -m evals.run`, see [docs/benchmark.md](docs/benchmark.md)) to ensure defect recall and precision do not regress.
